Bootstrapping Recommendations in a New Marketplace: A Practical Guide

Starting a recommendation system from scratch is one of the hardest problems in applied ML. You have no interaction data, sparse item catalogs, and users who will churn if their first experience feels irrelevant. This post covers practical strategies that work when you have nothing to train on.

The Cold-Start Trilemma

New marketplaces face three simultaneous cold-start problems:

  • Cold users — no purchase or browse history to personalize against
  • Cold items — no engagement signals to estimate quality
  • Cold system — no interaction matrix to learn latent factors from

You can’t wait for data to accumulate organically because poor recommendations suppress the very engagement you need. You have to bootstrap.

Phase 0: Before You Have Any Data

Content-Based Filtering from Item Metadata

Every marketplace has some item attributes at launch — categories, price, descriptions, images. Build a content-based system that recommends items similar to what a user is currently viewing. 

from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("all-MiniLM-L6-v2")

item_embeddings = model.encode(item_descriptions)


def get_similar_items(query_idx, top_k=10):
    scores = item_embeddings @ item_embeddings[query_idx]
    top_indices = np.argsort(scores)[-top_k - 1 : -1][::-1]
    return top_indices

This is table stakes. It won’t be great, but it’s deterministic and explainable.

Popularity Priors from Adjacent Signals

If you can’t personalize, at least don’t show garbage. Construct popularity priors from:

  • Seller reputation imported from other platforms
  • Search query volume from your own search logs (people search before they click)
  • External signals — review counts from public APIs, social mentions, category benchmarks

Rank by score = log(1 + external_signal) * quality_weight as your default fallback.

Curated Collections as Implicit Models

Human curation is an underrated bootstrapping strategy. Have domain experts build 20–50 themed collections. These serve as a manual “embedding space” — users who engage with Collection A are probably similar to each other. You’ve just created your first user segments for free.

Phase 1: First 1,000 Interactions — Explore Aggressively

Bandit-Based Exploration

Once you have a trickle of traffic, switch from static rankings to a bandit that explores deliberately.

Thompson Sampling works well here because it naturally explores uncertain items: 

import numpy as np

class ThompsonBandit:
    def __init__(self, n_items):
        self.alphas = np.ones(n_items)  # successes + 1
        self.betas = np.ones(n_items)   # failures + 1

    def select(self, candidates, n=10):
        samples = np.random.beta(
            self.alphas[candidates],
            self.betas[candidates],
        )
        selected = candidates[np.argsort(samples)[-n:][::-1]]
        return selected

    def update(self, item_id, reward):
        if reward > 0:
            self.alphas[item_id] += 1
        else:
            self.betas[item_id] += 1

The key insight: exploration is not wasted traffic in a cold marketplace — it’s your data collection strategy. Every impression that resolves uncertainty about an item’s quality pays dividends later.

Implicit Feedback Hierarchy

Don’t wait for purchases. Build a reward signal from the cheapest signals first:

│          Signal          │ Relative Weight │                     Why                      │
├──────────────────────────┼─────────────────┼──────────────────────────────────────────────┤
│ Purchase                 │ 1.0             │ Ground truth but sparse                      │
├──────────────────────────┼─────────────────┼──────────────────────────────────────────────┤
│ Add to cart              │ 0.6             │ Strong intent                                │
├──────────────────────────┼─────────────────┼──────────────────────────────────────────────┤
│ Detail page view > 30s   │ 0.3             │ Genuine interest                             │
├──────────────────────────┼─────────────────┼──────────────────────────────────────────────┤
│ Click from listing       │ 0.1             │ Weak but abundant                            │
├──────────────────────────┼─────────────────┼──────────────────────────────────────────────┤
│ Impression without click │ -0.05           │ Negative signal (careful with position bias) │
└──────────────────────────┴─────────────────┴──────────────────────────────────────────────┘

Blend these into a single reward for your bandit. You’ll iterate on weights later — the important thing is to start logging everything now.

Phase 2: 10K–100K Interactions — Collaborative Signals Emerge

Lightweight Matrix Factorization

You don’t need deep learning yet. Implicit ALS trains in seconds on 100K interactions and gives you real collaborative filtering: 

import implicit

model = implicit.als.AlternatingLeastSquares(
    factors=64,
    regularization=0.1,
    iterations=20,
)

# interaction_matrix: sparse CSR, users x items
model.fit(interaction_matrix)

# Get recommendations for user 42
recommendations = model.recommend(
    userid=42,
    user_items=interaction_matrix[42],
    N=20,
)

At this stage, your hybrid should be roughly: 0.6 × collaborative + 0.3 × content + 0.1 × popularity. Tune with online A/B tests.

Transfer Learning from Related Domains

If your company has an adjacent product with existing user data, transfer is powerful:

  • Pre-train item embeddings on the mature marketplace, fine-tune on your sparse data
  • Use shared user IDs to initialize user factors
  • Import category-level preferences (“users who buy premium electronics also buy premium audio”)

Even noisy transfer beats random initialization when you have 10K interactions.

Phase 3: Scaling Beyond Bootstrapping

Know When to Graduate

You’ve successfully bootstrapped when:

  • Collaborative filtering outperforms content-based in A/B tests (typically around 50K–200K interactions depending on catalog size)
  • Your bandit exploration budget can decrease without hurting next-week metrics
  • New items reach stable CTR estimates within 48 hours of listing

At this point, invest in proper ML infrastructure: feature stores, real-time inference, model retraining pipelines. The bootstrapping hacks should be replaced, not layered on top of.

The Feedback Loop Trap

One danger of bootstrapping: your initial heuristics create selection bias in the data you collect. Items you never show can never prove they’re good.

  1. Reserve 5–10% of traffic for uniform random exploration in early phases
  2. Log propensity scores (the probability that each item was shown) to enable off-policy correction later
  3. Periodically refresh — re-introduce items that were dismissed early with few impressions
# Log everything needed for future debiasing
log_entry = {

Architecture Principles

A few lessons that apply regardless of which phase you’re in:

  1. Separate retrieval from ranking. Even in Phase 0, have a candidate generation step (broad, cheap) and a ranking step (narrow, expressive). This lets you swap ranking models without rebuilding retrieval.
  2. Feature-gate, don’t branch. Run your content-based, bandit, and collaborative models behind the same serving interface. Promote whichever wins without redeploying.
  3. Optimize for learning speed, not model quality. In a cold marketplace, the model you’ll have in 3 months matters more than the model you have today. Instrument obsessively. Log generously. Make retraining trivial.
  4. Set calendar reminders to remove hacks. Bootstrapping strategies have expiration dates. The popularity prior that saved you in month 1 becomes a self-reinforcing rich-get-richer loop by month 6.

The meta-lesson: bootstrapping isn’t about finding one clever trick. It’s about having a deliberate progression plan where each phase generates the data needed to unlock the next phase. Design for the transition, not just for today.
