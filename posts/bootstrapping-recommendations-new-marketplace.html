Bootstrapping Recommendations in a New Marketplace: A Practical Guide

Imagine launching a new online marketplace with no customer history and no item reviews. You still need to suggest products that feel useful on the first visit. This guide walks through a simple, step-by-step way to start recommending items before you have much data.

What makes a new marketplace hard?

Recommendations work when you can see what people liked before. In a brand-new marketplace, you usually have three problems at once:

  • No user history — no one has bought or browsed enough to personalize their experience.
  • No item feedback — you don’t yet know which products customers like.
  • No data to learn from — algorithms need examples, and a new service has very few.

If you show bad recommendations early, users may leave and never return. So instead of waiting, you need to start with simple, reliable approaches and improve as you learn.

Phase 0: The first days with no data

Use product details to find similar items

You may not know customers yet, but you do know your products. Every item has a name, description, category, price, and maybe an image. If someone looks at one product, show other products that are similar.

This is called a content-based recommendation, and it helps you avoid showing something completely unrelated. It’s not personalized, but it is useful and easy to explain. 

from sentence_transformers import SentenceTransformer
import numpy as np

# Turn item descriptions into numerical vectors
model = SentenceTransformer("all-MiniLM-L6-v2")
item_embeddings = model.encode(item_descriptions)


def get_similar_items(item_index, top_k=10):
    # Compare this item to all others and return the most similar
    similarity_scores = item_embeddings @ item_embeddings[item_index]
    closest_matches = np.argsort(similarity_scores)[-top_k - 1 : -1][::-1]
    return closest_matches

This type of recommendation is deterministic: it will always show items that are close in content to what the user is viewing. That makes it a good first step for a new marketplace.

Fallback to popularity from outside signals

When you can’t personalize at all, show items that are likely to be good. You can estimate that from information outside your marketplace:

  • Seller reputation scores from other platforms
  • Search queries people type in your site search bar
  • Review counts, social mentions, or industry benchmarks

Combining those signals gives you a simple default ranking. It’s not perfect, but it keeps the first experience from feeling random.

Use curated collections as early personalization

People understand categories. Have your team create a small number of collections like “Best for Home Office,” “Gifts Under $50,” or “New Arrivals.”

These collections help in two ways: they give users a clear place to start, and they let you treat people who click the same collection as a similar group. That gives you a basic way to personalize without any machine data.

Phase 1: The first few hundred or thousand interactions

Explore deliberately, not randomly

Once the site has some visitors, you need to decide whether to show items that already look good or to test items you’re less sure about. If you only show the safest items, you learn less. If you explore too much, users may see too many bad recommendations.

A good strategy balances those goals by mostly showing likely winners while still testing uncertain items. This is often called a bandit strategy. 

import numpy as np

class ThompsonBandit:
    def __init__(self, n_items):
        self.wins = np.ones(n_items)
        self.losses = np.ones(n_items)

    def select(self, candidates, n=10):
        # Give each item a score based on how well it has done so far,
        # while still giving less-known items a chance.
        samples = np.random.beta(
            self.wins[candidates],
            self.losses[candidates],
        )
        chosen = candidates[np.argsort(samples)[-n:][::-1]]
        return chosen

    def update(self, item_id, reward):
        if reward > 0:
            self.wins[item_id] += 1
        else:
            self.losses[item_id] += 1

In plain terms: show items that have performed well, but also keep testing new possibilities. This helps you learn what works quickly.

Learn from clicks, not just purchases

A purchase is the strongest sign that a recommendation worked, but it is also the rarest early on. Instead, track every interaction that shows interest:

Action Weight Meaning
Purchase 1.0 Strong evidence the recommendation was good
Add to cart 0.6 Strong purchase intent
Viewed a product page for 30+ seconds 0.3 The user was interested enough to stay
Clicked from a listing 0.1 A mild sign of curiosity
Saw it but didn’t click -0.05 May indicate disinterest, but be careful of placement effects

The point is: don’t wait for expensive signals. Start collecting every useful clue now.

Phase 2: When patterns begin to show up

Let customer behavior suggest similar items

After 10K to 100K actions, you have enough history to see real patterns. One useful idea is: people who behaved like you also liked these items.

This is often called collaborative filtering. It is less about what the product is, and more about what people did with it. 

import implicit

model = implicit.als.AlternatingLeastSquares(
    factors=64,         # how many hidden patterns to learn
    regularization=0.1, # keep the model from overfitting
    iterations=20,      # how many passes over the data
)

# Train the model on user-item interactions
model.fit(interaction_matrix)

# Recommend items for a specific user
recommendations = model.recommend(
    userid=42,
    user_items=interaction_matrix[42],
    N=20,
)

At this stage, a good mix is usually: 60% behavior-based recommendations, 30% similarity-based recommendations, and 10% popularity fallback.

Use existing products as a starting point

If your company already has another product with customer data, you can borrow from it. For example, if people who buy premium electronics also like premium audio gear, that is useful information for a new marketplace too.

This is called transfer learning. It allows your new marketplace to benefit from experience that already exists elsewhere.

Phase 3: Scaling past the bootstrapping stage

Know when to move on

You can stop treating the site like an experimental playground when:

  • behavior-based recommendations consistently beat similarity-based recommendations
  • you can reduce exploration without hurting engagement
  • new products get enough attention quickly to be judged fairly

Once that happens, it is time to build more robust systems — automatic retraining, real-time personalization, and a cleaner way to manage product features.

Don’t let the early rules trap you

A common danger is that your early recommendation rules start shaping the data you collect. If you only show certain products, other products never get a chance. That makes your future system biased.

  1. Keep 5–10% of traffic for random exploration, so new items can be tested.
  2. Record how likely each item was to be shown, so you can correct for the fact that some items were shown more often.
  3. Give poorly seen items another chance later instead of assuming they’re bad forever.
# Log what was shown so you can fix bias later
log_entry = {
    "user_id": user_id,
    "item_id": item_id,
    "position": rank_position,
    "propensity": selection_probability,  # how likely it was to be shown
    "timestamp": now,
    "outcome": None,  # fill in later with click/purchase results
}

This kind of logging is easy to add and very valuable later on.

Design the system to evolve

  1. Separate finding items from ranking them. First find a reasonable set of candidates, then rank those candidates. That makes future changes much easier.
  2. Use the same serving interface. Whether your results come from manual collections, simple rules, or learned recommendations, serve them through the same API. That makes it easier to switch approaches later.
  3. Focus on learning fast. In a new marketplace, the model you have in a few months matters more than the one you ship today. Make it easy to log data and retrain regularly.
  4. Remove temporary hacks. Early tricks are useful, but they should be turned off when better data is available. Otherwise they become sources of bias.

Recap

Phase What you have Main approach Big risk
0 No data Use product similarity, curated collections, and external popularity Showing irrelevant items too early
1 Some traffic Explore deliberately and learn from many signals Collecting biased data if you don’t explore enough
2 More activity Use behavior-based recommendations + content + popularity Overfitting to your earliest users
3 Strong activity Build a full production recommendation system Keeping old hacks around too long

The main point is simple: bootstrapping recommendations is not one magic trick. It is a sequence of safer, easier choices that help you gather the data needed for the next step. Start with what you know, learn quickly, and make sure your early solutions can be replaced as your marketplace matures.
